Director decisions, triaged ready to decide first

Decision taskQuestion · recommendation · minimum actionStatusBlocked by nowImpact (unlock now · downstream)

Open decision tasks in launch scope (node type DECISION or the director workstream, not yet accepted), in three groups. Ready = every dependency is satisfied and no evidence is recorded as missing: these are the decisions to take now. Waiting = an open dependency, or the brief starts with "WAITING" (evidence such as a device session is still missing): do not decide yet. Future = on hold, deferred, or marked "FUTURE". Immediate unlock = open tasks that become dependency-ready the moment this decision is taken (all their other dependencies are already met); transitive downstream = everything that waits on it at any depth, which other gates may still hold. Unlocked effort is not completed effort.

    Deferred

    DONE (fully accepted)
    Status DONE or RELEASED.
    Director accepted, not yet DONE
    Status DIRECTOR_ACCEPTED, its own bucket (a subset of technically complete).
    Technically complete
    Status IMPLEMENTED, QA_PASS or DIRECTOR_ACCEPTED (not DONE). Reason for not DONE: device NOT TESTED if the device status says so, otherwise awaiting Director acceptance (IMPLEMENTED / QA_PASS), otherwise other.
    In progress / not started
    IN_PROGRESS / PLANNED or READY.
    Hold / blocked
    HOLD or BLOCKED within launch scope.
    Effort-weighted progress
    Base effort (effort_base_h) summed over launch scope, split into DONE / technically complete / remaining. Rows with zero or empty effort (decisions, gates) are counted above but carry no weight.

    Progress by milestone LAUNCH SCOPE

    MilestoneExecutableDONEDirector accepted (not DONE)Awaiting acceptanceIn progressNot startedHold / blockedOtherΣ checkRemaining base hNo estimate (task / decision)DONE %Technical readiness %

    Denominator per row = executable launch tasks in that milestone (EPIC / PARENT and CANCELLED excluded). The seven status columns are mutually exclusive and add up to Executable (Σ check): DONE = DONE / RELEASED; Director accepted = status DIRECTOR_ACCEPTED, not DONE (technical, specification or visual acceptance — the kind is in the Acceptance view); Awaiting acceptance = IMPLEMENTED / QA_PASS (a QA_PASS marked "technically complete" counts once, here); Other = any other status value. DONE % = DONE / Executable. Technical readiness % = (DONE + Director accepted + Awaiting acceptance) / Executable. Remaining base h = base effort of rows in progress, not started or on hold / blocked. No estimate = those open rows with base effort 0: work tasks are a real estimation gap; Director decisions carry 0 by design (Director latency), so a decision-only milestone can show "not started" with 0 remaining hours.
