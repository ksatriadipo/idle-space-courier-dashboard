    How progress is measured (D-100)
    Executable task
    Node type is not EPIC or PARENT. Containers are never counted.
    Launch scope
    Executable, milestone is not POST-LAUNCH / DEFERRED, and status is not CANCELLED (cancelled rows stay in the register). Every denominator on this page is launch scope unless it says otherwise.
    Deferred
    Executable rows in POST-LAUNCH / DEFERRED. Shown on a separate line, never as launch backlog.
    DONE (fully accepted)
    Status DONE or RELEASED.
    Director accepted, not yet DONE
    Status DIRECTOR_ACCEPTED, its own bucket (a subset of technically complete).
    Technically complete
    Status IMPLEMENTED, QA_PASS or DIRECTOR_ACCEPTED (not DONE). Reason for not DONE: device NOT TESTED if the device status says so, otherwise awaiting Director acceptance (IMPLEMENTED / QA_PASS), otherwise other.
    In progress / not started
    IN_PROGRESS / PLANNED or READY.
    Hold / blocked
    HOLD or BLOCKED within launch scope.
    Effort-weighted progress
    Base effort (effort_base_h) summed over launch scope, split into DONE / technically complete / remaining. Rows with zero or empty effort (decisions, gates) are counted above but carry no weight.
    Critical path
    Not published in the public data, so the PROVISIONAL launch forecast dates are shown instead.

    Launch scope by status

    Executable tasks are tasks, requirement items, gates, sessions and decisions. Epics and parent rows (node type EPIC / PARENT) are excluded so parent and child effort is never counted twice.
